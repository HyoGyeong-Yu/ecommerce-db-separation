# Trade-offs: 도메인별 DB 분리의 대가

이 프로젝트는 회원(RDS) / 결제(RDS) / 장바구니(DynamoDB)를 물리적으로 분리해
장애 격리(blast radius 최소화)를 얻었다. 그 효과는 장애 시나리오에서 실측으로 확인했다
— 회원 DB 커넥션 풀 고갈 중에도 결제·장바구니 API는 정상 응답(k6 5,000+ 요청, 성공률 100%).

하지만 **분리는 공짜가 아니다.** 이 문서는 분리로 지불한 4가지 대가와,
현재 규모에서 내린 판단을 기록한다.

---

## 1. 크로스 도메인 조회 — JOIN이 불가능하다

**문제**
회원과 결제가 서로 다른 RDS 인스턴스에 있으므로
`SELECT ... FROM members JOIN payments` 같은 단일 쿼리가 불가능하다.
"회원 이름 + 결제 내역" 화면 하나를 만들려 해도 DB 하나로는 답이 안 나온다.

**내 선택 (현재 규모)**
애플리케이션 레벨 조합. FastAPI에서 회원 조회 1회 + 결제 조회 1회 후
코드에서 합쳐 응답한다. 네트워크 왕복이 1회 늘어나는 비용을 감수했다.

**규모가 커지면**
조회 전용 읽기 모델(CQRS) 또는 읽기 전용 뷰를 별도로 구성해,
쓰기는 도메인별 DB에 / 조회는 통합 저장소에서 처리한다.

---

## 2. 트랜잭션 정합성 — 하나의 트랜잭션으로 묶을 수 없다

**문제**
주문과 결제가 다른 DB에 있으면 단일 DB 트랜잭션(COMMIT/ROLLBACK)으로
원자성을 보장할 수 없다. "결제는 성공했는데 주문 기록은 실패"라는
부분 실패 상태가 발생할 수 있다.

**내 선택 (현재 규모)**
애플리케이션 레벨 보상 로직. 결제 기록 실패 시 앞 단계 작업을
명시적으로 되돌리는 코드를 두는 방식으로 대응한다.

**규모가 커지면**
Saga 패턴 — 각 도메인의 로컬 트랜잭션을 이벤트로 연결하고,
실패 시 보상 트랜잭션을 발행해 정합성을 회복한다.

---

## 3. 비용 증가 — 인프라가 2배로 늘었다

| 항목 | 단일 DB 구성 | 현재 구성 |
|---|---|---|
| RDS 인스턴스 | 1대 | 2대 (member / payment) |
| DynamoDB | — | 1테이블 (cart) |
| ALB + ASG | — | 추가 (SPOF 제거) |

- 실측 월 비용: **$2.74 / 월** (Cost Explorer, 아래 스크린샷)
- 이 비용으로 산 것:
  - 장애 격리 — 한 도메인 장애가 다른 도메인으로 전파되지 않음 (k6 실측)
  - 자기치유 — EC2 강제 종료 → ASG가 약 2분 만에 대체 인스턴스 투입 (실측)

**역방향 실험도 했다.** DynamoDB를 프로비저닝 WCU 1로 낮춰 비용을 아끼는 선택은
곧바로 쓰기 스로틀링으로 이어졌고(fault-03), On-demand로 복귀했다.
비용 절감과 성능 여유는 항상 맞바꾸는 관계라는 것을 실측으로 확인했다.

---

## 4. 운영 복잡도 — DB가 3개면 운영 부담도 3벌이다

**문제**
백업 정책, 파라미터 그룹, CloudWatch 알람이 DB 수만큼 늘어난다.
게다가 DB마다 특성이 달라 알람 설계도 각각 달라야 한다.

**실제로 겪은 사례 (fault-03)**
DynamoDB 알람을 `ConsumedWriteCapacityUnits > 500`으로 걸어뒀는데,
실제 스로틀링이 발생해도 알람이 울리지 않았다.
스로틀링 감지에 맞는 메트릭은 `WriteThrottleEvents >= 1`이었고,
Terraform으로 알람을 수정한 뒤에야 MTTD 2분 10초로 감지에 성공했다.
"DB 종류가 늘면 각 DB에 맞는 관측 설계가 필요하다"는 비용을 몸으로 확인한 사례다.

**상쇄 전략**
모든 알람·설정을 Terraform 코드로 관리한다. 위 알람 수정도
콘솔 클릭이 아니라 코드 변경 → apply로 처리해, 재현 가능하고 리뷰 가능한
형태로 남겼다.

---

## 정리: 얻은 것 vs 지불한 것

| 얻은 것 (실측 근거) | 지불한 것 |
|---|---|
| 장애 격리 — 장애 중 타 도메인 성공률 100% | JOIN 불가 → 앱 레벨 조합 |
| 자기치유 — 인스턴스 교체 약 2분 | 분산 트랜잭션 불가 → 보상 로직 |
| 도메인별 독립 스케일링·보안 경계 | 월 $2.74 추가 비용 |
| | 알람·백업·파라미터 3벌 운영 |

**결론:** 이 규모에서는 "앱 레벨 조합 + 보상 로직 + Terraform 자동화"로
대가를 감당 가능한 수준으로 낮출 수 있다고 판단했다.
트래픽과 팀 규모가 커지면 CQRS / Saga로 전환하는 것이 다음 단계다.
